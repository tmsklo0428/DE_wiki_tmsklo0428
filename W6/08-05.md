## 📅 2026-08-05(수)

### 📝 Review

- **DE 프로젝트 아키텍처 학습**
  - 메달리온 아키텍처에서 Bronze, Silver, Gold 계층이 각각 원본 보관, 데이터 정제·통합, 최종 서비스 데이터를 담당한다는 점을 정리했다.
  - 데이터의 크기와 특성에 따라 Spark, GeoPandas, Pandas를 구분해 사용하는 기준을 파악했다.
  - Spark는 원본 데이터의 크기보다 `explode` 과정에서 발생하는 대용량 중간 데이터를 처리하기 위해 사용하는 것이라는 점을 알게 되었다.
  - LION과 Taxi Zone 데이터를 연결하기 위해 `dim_street_zone` 매핑 테이블이 필요한 이유를 파악했다.
  - 통행량은 단순 평균이 아니라 월별 계수와 요일·시간대별 평균을 함께 반영해야 실제 데이터 특성을 반영할 수 있다는 점을 정리했다.
  - 데이터 갱신 주기에 따라 Airflow DAG를 `@once`, `@monthly`, `@daily`로 분리하는 설계 근거를 파악했다.
  - 데이터 품질 검증은 수집, 정제, 집계 단계별로 수행해야 하며, 특히 Gold 단계의 집계 검증이 중요하다는 점을 알게 되었다.
- **W6M1 과제**
  - 서울시 API 기반 ETL 파이프라인을 구현했다.
  - Airflow와 Docker Compose를 이용해 실행 환경을 구축했다.
  - Delete-then-Insert를 적용해 동일한 데이터를 여러 번 실행해도 결과가 유지되도록 구현했다.
